# Real Migration Checklist

A generated file is not a completed migration.

- The correct source project, app identity and target environment are identified.
- Local source findings and installed account evidence are separately recorded.
- Official sources, schemas, deadlines and product entitlements were rechecked.
- Intended behavior and supported legacy features have acceptance tests.
- Unsupported fields/actions are explicit, not silently dropped.
- Auth, scopes, signatures and account isolation were reviewed independently.
- Existing host and working tokens are preserved unless a change is necessary.
- Local checks pass with synthetic data; skipped tests are reported.
- The exact live operation and test records have explicit user approval.
- Irreversible changes are described before approval, especially card view migration.
- Installed data, actions, permissions and source-record links are verified.
- The completion report distinguishes local tests, deployment and live verification.
- Remaining unknowns are visible; failures do not trigger automatic permission expansion.
- Private reports and secrets are excluded from publication.
